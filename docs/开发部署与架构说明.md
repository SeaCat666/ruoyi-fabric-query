# 面料查询系统开发部署与架构说明

## 1. 技术架构

系统采用前后端分离结构：

```text
浏览器
  │
  ├─ 开发：Vite Dev Server /dev-api
  └─ 生产：Caddy :8088 /prod-api
                    │
                    ▼
             Spring Boot :8080
                    │
          Service + MyBatis Mapper
                    │
                    ▼
             H2 文件数据库
```

生产环境只让后端监听 `127.0.0.1:8080`。Caddy 在本机 `127.0.0.1:8088` 提供前端静态资源，并把 `/prod-api/*` 代理到后端。临时公网访问由 cloudflared 主动建立出站隧道，不需要在路由器或 Windows 防火墙开放端口。

## 2. Maven 模块职责

- `ruoyi-admin`：应用入口、REST Controller、环境配置、SQL 初始化入口。
- `ruoyi-common`：领域实体、公共响应、注解、异常和工具。
- `ruoyi-system`：面辅料与库存业务 Service、Mapper 接口、MyBatis XML。
- `ruoyi-framework`：Spring Security、JWT、权限校验、异常处理、限流。
- `ruoyi-quartz`：Quartz 任务基础设施，当前没有业务任务。
- `ruoyi-generator`：RuoYi 代码生成能力。

前端 `ruoyi-ui` 按 `src/api`、`src/views`、`src/store`、`src/router` 分层。业务菜单由后端 `sys_menu` 动态返回，按钮权限使用 `v-hasPermi` 与后端 `@PreAuthorize` 双重约束。

## 3. 业务边界

### 3.1 档案

- 面料与辅料使用独立主表和独立供应商表，避免供应商混用。
- 面料成分是明细行，组合代码由多行成分推导。
- 实物图片使用一对多图片表保存原图、缩略图和排序号。
- 面料编号按年度并发安全生成，辅料编号格式为 `B-YYNNNN`。

### 3.2 库存

- `inventory_stock` 是档案在具体规格、颜色、单位下的库存批次。
- 入库单过账增加现存量并写入流水。
- 领用单先锁定库存，发料后扣减现存量与锁定量。
- 退回、取消、冲销不会删除历史，而是生成反向业务记录或流水。
- 已被库存引用的档案禁止删除，确保历史单据可追溯。

### 3.3 权限

- `admin`：系统、档案、库存全部权限。
- `fabric_manager`：面辅料档案、基础资料和主要库存业务。
- `fabric_entry`：录入与本人数据维护，以及授权的库存业务。
- `fabric_view`：只读查询。

权限由 `sys_user`、`sys_role`、`sys_menu`、`sys_user_role`、`sys_role_menu` 组合完成。

## 4. 数据库初始化

初始化脚本为：

```text
ruoyi-admin\src\main\resources\sql\init-h2.sql
```

`deploy\windows\initialize-database.ps1` 仅在数据库文件不存在时执行初始化，防止重启时覆盖账号、配置或业务数据。实时数据库位于 `ruoyi-admin\data`，已被 Git 忽略。

面辅料与库存自动造数开关默认全部关闭。CSV 文件和图片目录仅用于开发阶段一次性导入，不属于正式部署数据。

## 5. 构建与验证

后端：

```powershell
mvn clean install -DskipTests
```

前端：

```powershell
Set-Location ruoyi-ui
npm install
npm run build:prod
```

初始化临时验证库：

```powershell
$tempDatabase = Join-Path $env:TEMP 'fabric-query-check\fabric'
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\deploy\windows\initialize-database.ps1 `
  -DatabasePath $tempDatabase
```

验证完成后，只能删除自己创建并确认位于 `%TEMP%` 下的临时目录。

## 6. Windows 生产进程

- `StartProduction`：登录 Windows 后启动后端、Caddy、cloudflared。
- `WatchProduction`：每 5 分钟检查 PID 身份和 8080/8088 端口，异常时重启完整栈。
- `DailyBackup`：每天 02:00 备份 H2，并镜像上传目录。

部署脚本使用相对项目路径，可以从其他盘符运行。Caddy 与数据库路径通过环境变量传入，不把本机绝对路径写入 GitHub。

## 7. 备份与恢复原则

- H2 使用在线 `BACKUP TO` 生成一致性 ZIP。
- 上传目录使用 robocopy 镜像。
- Git 仓库只保存架构和初始化 SQL，不保存实时数据库。
- 删除业务数据前先执行 `backup-data.ps1`。
- 恢复数据库时必须先停止后端，避免同时打开同一 H2 文件。

## 8. 二次开发入口

新增业务模块时保持现有模式：

1. `ruoyi-common` 添加领域实体。
2. `ruoyi-system` 添加 Mapper、Service 和 XML。
3. `ruoyi-admin` 添加 Controller 和权限注解。
4. `ruoyi-ui/src/api` 添加 API 封装。
5. `ruoyi-ui/src/views` 添加页面。
6. 在 `init-h2.sql` 添加表、索引、菜单和角色授权。
7. 先验证后端构建，再验证前端生产构建和真实页面权限。
