# 面辅料库存管理模块设计

## 1. 源数据审计结论

源目录 `C:\Users\admin\Desktop\面辅料库存管理` 包含 1 个 Excel 工作簿和 62 张图片。

工作簿 `面辅料库存管理.xlsx` 有 3 个工作表：

| 工作表 | 数据范围 | 数据量 | 列 |
| --- | --- | ---: | --- |
| 一料款多款开发备料 | A1:R63，表头第 2 行 | 61 | 物料编号、开发款号、图片、SKC、色号、备料量、单位、物料类型、货品类型、备注、领用单、领用货量、添加库存、入库单、现库存量、最后统计时间、关联、关联 1 |
| 设计师领用单 | A1:F3 | 2 | 订单编号、下单日期、领用人、下单商品、领用月份、锁定数量 |
| 入库单 | A1:F2 | 1 | 入库编号、入库日期、入库商品、入库操作人、数量、采购月份 |

主表 61 行中，物料编号缺失 33 行、SKC 全空、领用单/领用货量/添加库存/入库单/关联全空；备料量 54 行有值，现库存量 61 行有值。54 行可比数据的备料量与现库存量完全相等，说明当前是初始盘点快照，并非由流水计算得到。物料编号 28 行仅有 18 个唯一值，开发款号 61 行有 33 个唯一值；同一物料、款号和颜色存在重复行，因此库存批次不能在这些字段上加唯一约束。

源数据主计量单位几乎全部是“条”，但备注中频繁记录“米”；领用单的 200 与主表备注“200米”能对应。系统必须同时保存包装数量和实际长度，不能只保存一个库存数。

62 张图片共约 37.8 MB，其中 57 张为无扩展名 JPEG、5 张 PNG。文件名主要为 `物料编号_毫秒时间戳-哈希`，33 张以“未命名记录”开头，正好对应 33 行缺失物料编号的数据。图片既有面料卷实物图，也有成衣/款式图，所以图片保存时区分“物料图”和“款式图”。工作表每行都有图片锚点，其中一行有两张图，导入按图片锚点和数据行建立准确关联。

## 2. 业务判断

源表表达的实际流程是：开发款提出备料需求，物料按条入库，同时记录可选的米数；设计师领用时先锁定库存，实际发料后扣减库存；撤销锁定时释放，退料时回增。入库、领用和退回不能直接改余额，必须生成库存流水。

面料档案、辅料档案是基础资料；库存台账是批次与实物状态。库存通过 `fabric_id` 或 `accessory_id` 可选关联档案，同时保留物料编号、开发款号、颜色等快照。历史 Excel 编号与现有测试档案编号不一致时不强行关联，避免错误归档。

## 3. 数据库设计

### 3.1 inventory_stock 库存台账

- `id bigint` 主键
- `stock_code varchar(30)` 库存行编号，唯一
- `material_type char(1)`：F 面料、A 辅料
- `fabric_id bigint`、`accessory_id bigint`：二选一可空档案关联
- `material_code varchar(80)`、`development_style_no varchar(100)`、`skc varchar(100)`、`color_no varchar(100)`、`goods_type varchar(100)`：业务快照
- `primary_unit varchar(20)`、`auxiliary_unit varchar(20)`：主/辅助单位
- `on_hand_qty decimal(18,3)`、`locked_qty decimal(18,3)`：现有/锁定主数量
- `on_hand_aux_qty decimal(18,3)`、`locked_aux_qty decimal(18,3)`：现有/锁定辅助数量
- `last_count_time datetime`、`version int`、`del_flag char(1)` 及通用审计字段
- 索引：库存编号唯一；物料类型+档案；物料编号；开发款号；最后统计时间

### 3.2 inventory_stock_image 库存图片

保存库存行、原图、缩略图、图片类型、原文件名、排序和内容哈希；库存行删除时级联删除。

### 3.3 inventory_inbound_order / inventory_inbound_detail 入库单

主表保存单号、日期、状态（DRAFT/POSTED/CANCELED）、操作人、备注；明细保存库存行、主数量和辅助数量。草稿可修改删除；过账后增加库存并写入流水；冲销时检查可用库存，写反向流水，不物理删除历史业务。

### 3.4 inventory_requisition_order / inventory_requisition_detail 领用单

主表保存单号、日期、领用人、开发款号、状态（DRAFT/LOCKED/ISSUED/CANCELED/RETURNED）及审计字段；明细保存库存行和双数量。锁定增加锁定量；发料同时减少现有量和锁定量；取消释放锁定；退料增加现有量。

### 3.5 inventory_movement 库存流水

流水只新增不修改，记录 OPENING、INBOUND、INBOUND_CANCEL、LOCK、RELEASE、ISSUE、RETURN、ADJUST，保存业务单号、数量变动、变动后余额、操作人与时间。库存异常可追溯到具体业务单。

### 3.6 inventory_code_sequence 编号序列

按编号类型和日期维度保存最后流水值；数据库行锁加事务生成编号，避免并发重复。

## 4. 后端与前端文件

后端新增库存实体、`InventoryMapper`/XML、`InventoryService`、`InventoryController`、`InventoryNumberUtils` 和 `InventoryDataInitService`。接口遵循现有 `AjaxResult`、`TableDataInfo`、`@PreAuthorize`、`@Log`、`startPage()` 及 MyBatis XML 风格。

前端新增 `src/api/inventory/inventory.js`，页面为库存台账、入库单、领用单和库存流水。页面统一使用 Element Plus 查询表单、表格、分页、抽屉/对话框、权限指令和二次确认。

菜单新增“库存管理”目录，包含“库存台账、入库单、领用单、库存流水”。库存主管拥有全部权限，录入员可维护草稿并执行日常入库/锁定/发料，查询员只有查询权限；库存调整、已过账冲销等高风险操作仅主管和管理员可执行。
